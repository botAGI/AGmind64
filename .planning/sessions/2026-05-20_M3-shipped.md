## Phases shipped (in order)

### M3.P.fix — version_check tag filter (`b04a1b5`, ~1h)

**Driver:** weekly Phase P report содержал false positives — variant
suffix tags (Windows / arm64 / alpine / oracle), RC / dev / nightly tags,
SHA-only hashes, и branch-style tags из registries отображались как
"newer versions" против plain semver pins.

**Changes:**
- `_VARIANT_TOKENS` extended: oracle, builder, otel, boringcrypto, busybox,
  gpu-nvidia, cuda, rocm, vulkan, node, hadoop, kafka, spark
- `_NUMERIC_BUILD_SUFFIX_RE` — `-{6+digits}` filter (например `13.1.0-25893932881`)
- `_EMBEDDED_DATE_RE` — YYYYMMDD anywhere в tag (например `2.6-20260518-...`)
- `_BRANCH_NUMERIC_PREFIX_RE` — `4-27-app-deploy`-style branch tags
- `_compare()` сравнивает только `(major, minor, patch)` tuple, не prerelease
  components → fixes "? unknown" status для `caddy:2.11.3-alpine` vs `2.11.3`
- `_quay_latest(owner, image)` — quay.io v1 API (minio, docling)
- `_gcr_latest(project, image)` — gcr.io v2 anonymous (cadvisor)

### M3.Q — `agmind models {list,pull,rm,info}` (`59334d3`, ~2h)

**Driver:** `agmind/cli/models_cmd.py` существовал с `cmd_list/cmd_download/
cmd_verify/cmd_path` (legacy registry tier ops) — но НЕ зарегистрирован в
typer app. M3.Q добавляет 4 новых subcommands + регистрирует все 6.

**New functions:**
- `cmd_list_local(as_json)` — scan /var/lib/agmind/models/ для `.gguf`/
  `.safetensors`/`.bin` + size + mtime
- `cmd_info(model_id, file)` — curated catalog lookup или local file inspect
- `cmd_pull(model_id, repo, file, force)` — curl-based download с resume.
  Skip if already present.
- `cmd_rm(model_id, file, force)` — delete + warn если referenced в
  /opt/agmind/.env (use `--force` to override)

**CLI:**
```
agmind models list    --local/--catalog --json
agmind models info    <id> | --file X
agmind models pull    <id> | --repo X --file Y [--force]
agmind models rm      <id> | --file X [--force]
agmind models path    <name> --tier T (legacy)
agmind models verify  --tier T (legacy)
```

19 new tests `tests/test_models_cmd.py`.

### M3.R — `agmind upgrade` lifecycle (`6a900cf`, ~2h)

**Driver:** для bump одного image pin сейчас нужно edit YAML руками +
`agmind deploy --apply`. Хочется one-shot.

**New module `agmind/cli/upgrade_cmd.py`:**
- `cmd_check()` — subprocess wrapper for `scripts/version_check.py`
- `cmd_component(service, version, force, digest)` — replace image: tag
  + digest: line в `templates/services/<service>.yaml`. Saves rollback
  state to `~/.local/share/agmind/upgrades/<ts>_<service>.json`.
- `cmd_apply(install_dir, healthcheck_timeout)` — reuses Phase L.B
  `deploy.runner.deploy()` с automatic snapshot + rollback on failure.
- `cmd_rollback()` — reads latest upgrade state → restore old tag/digest
  → archives state to `rolled_back/` subdir.

**Holds protection:** reads `templates/version_holds.yaml` (Phase P).
If image held — refuse без `--force` с printed reason.

**CLI:**
```
agmind upgrade --check                       # scan
agmind upgrade --component X -v Y            # bump pin
agmind upgrade --component X -v Y --apply    # bump + redeploy
agmind upgrade --apply                       # redeploy after manual edit
agmind upgrade --rollback                    # revert last bump
agmind upgrade -c X -v Y --force             # bypass holds
```

15 new tests `tests/test_upgrade_cmd.py`.

### M3.S.2 — Multi-step wizard split (`7cd1293`, ~4h)

**Driver:** single-screen wizard с 7+ sections (cognitive overload per
Textual UX research).

**Architecture:**
- NEW `agmind/cli/tui/wizard_screens.py` (~350 LOC):
  - `_make_step_header(n, total, title)` — "Step N of M ● ● ○ ○" indicator
  - `DomainScreen` (1/4) — domain + CF token (с inline validators из S.1)
  - `ModelScreen` (2/4) — curated/custom model + ctx + kv + threads + parallel
  - `ServicesScreen` (3/4) — per-tier service checkboxes (Phase J.1.8 layout)
  - `ConfirmScreen` (4/4) — summary + [Back] [Apply]
- Navigation: Next button OR Alt+N, Back button OR Alt+B, Apply Ctrl+S
- State shared через `self.app.state` (existing SetupState)
- ConfirmScreen.action_apply hands off в root app's `action_submit()`
  (preserves existing deploy flow)

**Backward compat — opt-in:**
- `AGMIND_WIZARD_MULTISTEP=1` env → multi-step
- `AgmindSetupApp(multi_step=True)` kwarg (overrides env)
- Default → legacy single-screen (existing tests + UX unchanged)

9 new tests `tests/test_wizard_multistep.py` (config flags + Pilot smoke).

## Lessons / process

1. **Sequential phase planning works** — M3 had 6 phases with clear DoD
   per phase в ROADMAP.md. Following the list гарантирует closure.
2. **Validator pattern decoupled** — DomainValidator / TokenLengthValidator
   defined в `setup_wizard.py` reusable между legacy + multi-step
   screens (M3.S.2 imports их без duplication).
3. **Opt-in feature flags** для drastic UX changes (multi-step wizard
   via AGMIND_WIZARD_MULTISTEP) — позволяет ship'ить новое без ломания
   existing tests + workflow.
